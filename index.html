🔍 What Happens When You Type a URL
1. Browser checks its own DNS cache 2. OS checks system DNS cache (/etc/hosts) 3. Query goes to DNS Resolver (your ISP) 4. Resolver asks Root DNS Server 5. Root points to TLD server (.com, .org) 6. TLD server points to Authoritative DNS 7. Authoritative DNS returns IP address 8. Browser connects to IP via TCP (3-way handshake) 9. If HTTPS → TLS handshake happens 10. Browser sends HTTP GET request 11. Server processes request 12. Server returns HTTP response (HTML) 13. Browser parses HTML, finds CSS/JS/images 14. Browser fetches sub-resources (parallel) 15. Browser renders the complete page

💻 Circuit Breaker — 3 States
CLOSED → Normal. Requests pass through. If failures > threshold → go to OPEN OPEN → Failing. All requests rejected instantly. After timeout period → go to HALF-OPEN HALF-OPEN → Testing. Let 1 request through. If success → go back to CLOSED If fail → go back to OPEN

📋 How to Approach Any Design Problem
Step 1: CLARIFY requirements (5 min) → Functional: what does it do? → Non-functional: scale, latency, availability? Step 2: ESTIMATE scale (5 min) → Daily active users? → Read/Write ratio? → Data size per day/year? Step 3: HIGH-LEVEL design (10 min) → Draw main components → Client → LB → API → DB → Cache Step 4: DEEP DIVE (15 min) → Pick 2-3 complex components → Database schema → API design → Key algorithms Step 5: IDENTIFY bottlenecks (5 min) → Single points of failure? → How to scale each component?
