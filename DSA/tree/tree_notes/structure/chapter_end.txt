CHAPTER REVIEW TEMPLATE  (99_chapter_end.tex)     12-25 pages
=======================

Sections, in this fixed order (all via \chaptersection -- unnumbered, TOC entries):

  1. Chapter N Summary              results table + algorithms table
  2. Master Decision Flowchart      the post-study revision ladder
  3. Common Mistakes Checklist      trap | symptom | fix
  4. WA Clinic                      NEW - symptom -> cause -> fix decision TREE
  5. Quick Reference Card           formulas + minimal code, ASCII trees allowed
  6. Write-From-Memory Drills       NEW - fill-in-blank signature skeletons
  7. Complete Problem Checklist     every problem of the chapter, square Done? column
  8. Recommended Study Order        day-by-day path through the chapter
  9. Difficulty Progression         star tiers WITH \lv badges, what each tier proves
 10. Reduction Gallery              NEW - disguised problems that collapse to this
                                    chapter's tools
 11. Mixed Problem Set              mixedset, topic not revealed in hints
 12. The Summit                     NEW - one CF 3000-3500+ solved red-coder style
 13. Tool Kit Inventory              NEW - cumulative table of every tool so far
 14. Related Topics                 backward/forward links, one line each
 15. Last Word                      closing box, unique per chapter

ANTI-REPEAT RULE for this file: it is a REVISION file. Tables and one-liners only;
every entry points back with \thmref/\probref/\secref. No derivation prose, no
re-explained examples. If a sentence could have been written in a topic file, it
belongs there and must not appear here.

1. SUMMARY TABLES
   - Key results:  Result | One-line statement (with conditions!) | Where (\thmref)
   - Algorithms:   Algorithm | Time | Memory | WHEN TO USE (deciding phrase) | Code
     The "when to use" column is what makes the table a decision tool, not an index.

2. MASTER DECISION FLOWCHART
   ASCII tree in a plain lstlisting (language={}, numbers=none, frame=single) --
   NOT \verb, NOT verbatim. A YES/NO question ladder: start from "what does the
   problem ask?", branch on structure/operation, each leaf = [N.k] section ref or
   a pointer to the right later chapter (\chref). Keep lines <= 78 chars.
   It must DECIDE, not decorate: a reader who walks it never opens the wrong topic.
   Difference from the opener guide: opener routes by PROBLEM PHRASING before study;
   this routes by STRUCTURED QUESTIONS after study, including the "bends anywhere /
   carries information / repeated ops" style forks the flat guide cannot show.

3. COMMON MISTAKES CHECKLIST
   itemize, one line each, format "<mistake> -- <fix>", with the chapter's real traps
   (missing \nil{} base, depth vs height, no parent in general-tree DFS, stack on a
   skewed tree, overflow on sums/2^h, 0- vs 1-indexing, forest treated as one tree...).

4. WA CLINIC  (a judge-verdict debugging decision tree -- draw it, do not just table)
   TikZ decision TREE (diagrams.txt recipe): root "your verdict on the judge",
   branches WA/TLE/MLE/RE, each leaf = cause + the one-line fix + pointer to the
   \probref or pitfall where the chapter trained it. Only verdicts this chapter's
   problems can actually produce. A compact backup table under the figure.
   This section is where the per-problem hardeningbox notes POINT to (no repeats).

5. QUICK REFERENCE CARD
   \begin{quickref}[Chapter N at a glance] ... \end{quickref}
   A long code listing goes AFTER the box (a full lstlisting), never inside a macro
   argument. Reference the topic listings via \coderef instead of reprinting bodies.

6. WRITE-FROM-MEMORY DRILLS
   3-5 of the chapter's signature skeletons (DFS-with-parent, two-channel bottom-up
   return, iterative stack traversal, Euler in/out bracket, push/pull segment step...)
   as SHORT lstlistings with the key 1-3 lines replaced by ____ (blank macro:
   \% fill-in: $\underline{\hspace{2.2cm}}$), the answers one line below each listing
   (or at the section end). Rule: a drill line must come from a listing that exists
   in the chapter (\coderef it); the reader trains recall, the book forbids re-teaching.

7. COMPLETE PROBLEM CHECKLIST
   Each row's
   "Key technique" cell starts with the badge (\lv{3} two-channel return).
   \begin{table}[H]\footnotesize\centering
   tabular {@{}c p{0.17\linewidth} l p{0.20\linewidth} p{0.24\linewidth} c@{}}
   # | Problem | Source | Key technique | What to look for | Done?
   one row per W/Q/M problem of the chapter, grouped by a \multicolumn shaded row
   per section; Done? cell = $\square$ (blank square the reader ticks on paper).
   Cite sources by NAME+number only ("LC 110") -- never re-print URLs here
   (the URL-equals-once rule is enforced by the solved/practice entries).

8. RECOMMENDED STUDY ORDER
   Day | Task | Output table (10-14 days typical): read section -> solve which
   problems -> what to be able to write from memory. Solving order may differ from
   the book's section order -- say which problems to postpone and why.

9. DIFFICULTY PROGRESSION
   Tier | Problems | What passing this tier proves  ($\bigstar$ x difficulty, and
   every tier row opens with its badge \lv1..\lv6).
   Tiers are competency gates, not just rating buckets: name the skill each unlocks
   ("two-channel return values", "undo shared state on backtracking").

10. REDUCTION GALLERY  ("the tree is a disguise")
   6-10 entries, each ONE line + pointer: <problem/idea family> $\longrightarrow$
   <which chapter tool it collapses to>. Real CF/ICPC flavor, \lv4+: tree + binary
   search on the answer; tree DP + small-k bitmask; greedy exchange proof ON a tree;
   interval structure that IS a subtree; BFS layers that ARE levels of a virtual tree.
   Entries that name an outside problem obey the URL-once rule; otherwise describe
   the family ("jobs on a rooted tree with deadlines") without inventing links.
   Figures: one tiny before/after sketch per entry when the reduction is structural.

11. MIXED PROBLEM SET
   \begin{mixedset} \practice{...}{...}{...}{...}{hint} \end{mixedset}  -> M<ch>.<i>
   5-8 problems combining chapter topics; hints must NOT name the topic;
   difficulty spread \lv3..\lv5, badges shown, "no hint reveals the tool" rule intact.

12. THE SUMMIT  (the chapter's top rope -- one CF 3000-3500+ solved red-coder style)
   \solvedproblem with {CF <official rating> \lv{6}}, solved with the FULL
   solved_problem.txt pipeline plus two extra steps BEFORE the solution:
     (a) THE DISGUISE: restate the problem as it presents; figure.
     (b) THE REDUCTION: how a strong competitor finds "what it really is" --
         the named chapter tool + the foreign ingredient; second figure showing
         the transformed structure; thinkbox with the two dead ends \lv4 solvers
         hit here (that is WHY this problem is 3000+).
   Then after the solution: "why each lower rung fails" -- one line per rung of the
   chapter's own ladder that does NOT survive, with the killing constraint.
   Budget 3-6 pages. Hard rule: the Summit problem must reuse >= 2 chapter tools
   and >= 1 tool from an EARLIER chapter (that is the \lv5-6 signature: composition).

13. TOOL KIT INVENTORY  (cumulative -- the machine assembled so far)
   Table: Tool | Since ch | Level | One-line trigger phrase | Where.
   Rows = every technique introduced up to AND including this chapter (copy the
   previous chapter's table, add this chapter's rows -- pointers only, never prose).
   Grows across the 31 chapters; by ch31 it is the reader's personal cheat sheet.

14. RELATED TOPICS
   \chref/\secref links, backward and forward, one line each: what that chapter adds.

15. LAST WORD
   \begin{lastword}[Last Word -- Chapter N]
     an honest opening quote (attributed); one short paragraph tying the chapter's
     one big idea to daily practice; 2-3 numbered reflexes; 3-4 habit bullets;
     a "Next: \chref{...}" line; end centered $\blacksquare$ + one-sentence rule.
   UNIQUE CONTENT ONLY: no recap of tables, no new technique. Each chapter's Last
   Word argues a different thesis -- if two chapters' Last Words could swap, one
   of them was written lazily; rewrite it.
