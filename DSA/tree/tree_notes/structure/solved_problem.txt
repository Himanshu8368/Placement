SOLVED PROBLEM TEMPLATE                          target 1.5-3 pages each
=======================

Steps, in this fixed order (mirrors the DP series' 6-section problem template,
adapted: their 4-stage linear-DP ladder becomes our brute -> better -> optimal
APPROACH LADDER, since tree problems span many pattern families, not one pipeline):

  problemstatement box     restatement, IO, constraints, example
  0. Attempt Gate              (NEW - attemptgate box: "20 minutes, paper first";
                                \peek / \nudge / \fullhint unlock in that order;
                                the full solution follows anyway -- the gate makes
                                the reader COMMIT before reading, not hide hints)
  1. Understanding the Problem
  2. Key Observations            (numbered observation envs, 2-4, each justified)
  3. Think It Through With Me    (NEW - thinkbox: 1-3 REALISTIC dead ends via
                                \deadend{attempt}{what kills it}, then \aha{idea};
                                mandatory for every \lv3+ full solution)
  3½. The Approach Ladder        (mandatory whenever a non-obvious jump exists
                                between brute force and the intended solution;
                                each rung starts with its badge \lv{n})
  4. Solution                    (the winning rung, told in full)
  5. Proof of Correctness
  6. Implementation
  7. Trace                       (tracebox on the chapter running example)
  8. Complexity                  (complexitybox + comparison table across all rungs)
  9. Verification and Edge Cases (small table: case | what the code does)
 10. Pitfalls and Variants
 11. Key Takeaways               (insightbox: the 3 things worth memorising,
                                  phrased as transferable lessons, not this problem)
 12. AC -> Red hardening note    (NEW - hardeningbox: what BREAKS when the judge
                                  is adversarial: skewed depth vs stack limit,
                                  memory-tight child storage, time-tight traversal
                                  order, overflow; \lv4+ solutions must state the
                                  iterative/memory variant even if unused)

\begin{problemstatement}
  Paraphrase in your own words (never paste the statement). Input, output and ALL
  constraints. One small example, with the tree drawn if it helps.
\end{problemstatement}

\begin{attemptgate}[Attempt it yourself first -- \lv{3}, give yourself 20 minutes]
  <one sentence: what a fair first attempt looks like.>

  \nudge{<the decisive question + the shape of the return value, no code>}

\solstep{Understanding the Problem}
  Restate the task in tree language (what is a node, what must be returned). What makes
  it hard (look at the constraints, the shape of the tree). The brute force and why it
  is too slow, or why recursion is natural.

\solstep{Key Observations}
  \begin{observation} ... \end{observation}      2-4 of them, each justified
  (Observations are numbered 1, 2, ... automatically, per problem.)

\solstep{Think It Through With Me}   [thinkbox -- for \lv3+ solutions]
  Show the search, not just the find. A typical arc:
  \deadend{<the obvious but wrong-first idea>}{<the concrete case that breaks it,
          with a mini figure when the failure is structural>}
  \deadend{<the almost-right idea>}{<what is missing>}
  \aha{<the correct reframing -- in the reader's own vocabulary>}
  RULES: dead ends must be ideas a real solver actually has (never strawmen);
  each kill is a CHECKABLE fact (a counterexample tree, a constraint, a TLE math);
  the \aha line is exactly the Key Observation that the ladder's winning rung uses
  -- thinkbox motivates, the ladder quantifies, no prose is repeated between them.

\solstep{The Approach Ladder}   [compact form -- use when rungs are one-liners]
  \begin{center}\renewcommand{\arraystretch}{1.3}
  \begin{tabular}{@{}c p{0.235\linewidth} p{0.28\linewidth} l c@{}}
  \toprule
  \textbf{\#} & \textbf{Approach} & \textbf{Idea} & \textbf{Time} & \textbf{Verdict} \\
  \midrule
  1 & \lv{1} <brute> & <one-line idea> & $O(n^2)$ & \tle \\
  2 & \lv{3} <better> & <the key insight> & $O(n)$ & \ac \\
  \bottomrule
  \end{tabular}\end{center}
  Verdict macros: \ac \tle \mle \re \ce  (Accepted / TLE / MLE / RE / CE).
  Verdict cells stay SHORT (the stamp only); explain a verdict in one sentence of
  prose AFTER the table. Keep notes out of the cells -- they overflow the column.
  For a long ladder (full code per rung) use instead:
  \begin{approachbox}{Approach N -- <name>}{Time: $O(...)$. Space: $O(...)$}
    <Idea> <Why it fails or wins> <code if it teaches something>
  \end{approachbox}
  RULE: the last rung IS the Solution step's approach; steps 4-11 then continue
  from it without re-explaining. A problem whose brute->optimal jump is trivial
  (LC 104-class) may skip the ladder -- say so rather than pad.

\solstep{Solution}
  The algorithm in words or pseudocode, plus a FIGURE on the sample input showing the
  tree and, if relevant, the visited order or the returned values per node.

\solstep{Proof of Correctness}
  A full argument (a proofbox is fine), usually induction on the tree, citing the
  topic's theorems (\thmref ...). State the base case (\nil{} or a leaf) explicitly.

\solstep{Implementation}
  \begin{lstlisting}[caption={<Title> (<Judge ID>)}, label={lst:cNN-<slug>}]
  complete, compiling C++ (#include <bits/stdc++.h>, using namespace std;)
  For binary trees, include the standard struct:
      struct TreeNode { int val; TreeNode *left, *right;
                        TreeNode(int x=0): val(x), left(nullptr), right(nullptr) {} };
  \end{lstlisting}

\solstep{Trace}
  \begin{tracebox} step-by-step on the CHAPTER RUNNING EXAMPLE (the same tree the
  topic's worked example uses -- do not invent new data per problem), showing call
  order / returned values / state changes, one line per step. \end{tracebox}

\solstep{Complexity}
  \begin{complexitybox} time and memory, compared with the limits; say the recursion
  depth (worst case O(n) for a skewed tree) and whether an iterative version avoids it.
  \end{complexitybox}
  Then, when a ladder exists, the comparison table:
  \begin{center}\renewcommand{\arraystretch}{1.2}
  \begin{tabular}{@{}lccccl@{}}
  \toprule
  \textbf{Approach} & \textbf{Time} & \textbf{Space} & \textbf{Gain} & \textbf{Verdict} \\
  \bottomrule
  \end{tabular}\end{center}
  Gain = what buying the speedup cost (the trick used). One line per rung.

\solstep{Verification and Edge Cases}
  Small table (Edge case | Why it is tricky | What the code does). Standard set for
  trees: single node; skewed chain; one child only; values at INT_MIN/MAX; result
  overflowing int; empty subtree / \nil{} return. Only rows the problem can actually hit.

\solstep{Pitfalls and Variants}
  warningbox for traps (missing \nil{} base case, skewed tree blowing the stack,
  depth vs height off-by-one, integer overflow on sums/counts, not passing parent in a
  DFS on a general tree); 1-3 variants ("twist X -> technique Y", point at the
  \probref or \secref that covers it).

CODE RULES
  - Test on the samples before writing the listing down.
  - long long whenever a count/sum can exceed 2^31 (subtree sums, path counts, 2^h).
  - Binary trees: recursion is fine but always give the iterative form when depth can be n.
  - General/rooted trees: store as vector<vector<int>> adj and pass the parent to avoid revisits.
  - Fast IO for large inputs. Comments explain the tree idea, not the syntax.
  - ASCII only. The code must not be passed as a macro argument.
