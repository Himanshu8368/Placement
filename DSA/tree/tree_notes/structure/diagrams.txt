DIAGRAM RULES
=============

DIAGRAM-FIRST RULE (chapter.txt hard rule 8): any new idea, dead end, decision
or transformation gets a FIGURE before it gets a paragraph. A long chapter stays
readable only at roughly one third pictures. No figure-free page.

HOW MANY
- At least 10 figures per topic file: 1+ in Intuition, 1+ per major property/algorithm
  subsection, 1+ per solved-problem thinkbox dead end (mini sketch), 1+ per worked
  example, and a small sketch inside or beside every pattern card when the pattern is
  structural. Trees are visual by nature -- when in doubt, draw it.
- NEW mandatory structures each need their picture, listed where they occur:
    opener        ladder staircase (below) + roadmap,
    thinkbox      mini sketch per structural \deadend,
    WA Clinic     verdict decision TREE (below),
    gallery/Summit  before/after reduction pair (disguise -> true structure).

PATTERN
  \begin{figure}[H]
  \centering
  \begin{tikzpicture}[diagram]
    ...
  \end{tikzpicture}
  \caption{<What to notice, one or two sentences.>}\label{fig:cNN-<slug>}
  \end{figure}
  Refer to it in the text: \figref{cNN-<slug>}.
  Openers and chapter reviews use \caption*{...} (unnumbered).

SHARED STYLES  (setup/diagrams.tex; do not define new ones in chapters)
  diagram      base style for every tikzpicture (put in the [ ] of tikzpicture)
  -- general --
  numnode      circle with a number        boxnode   rounded box with text
  cellnode     square cell (arrays, grids)  hl hlblue hlgreen hlred hlpurple  fills
  flow         main arrow                  softarrow  secondary arrow
  guide        dashed helper line          brace / mbrace  curly braces (labelled)
  annot        small grey annotation text
  -- trees (manual TikZ, for annotated trees) --
  tnode        tree node (blue circle)      troot  root node (orange)  tleaf leaf (green)
  nullnode     small open circle for a missing child
  tedge        parent-child edge            tedgehl  highlighted edge
  subtreebox   dashed box that fits a subtree (use with [fit=(a)(b), subtreebox])
  -- trees (forest, auto layout; no coordinates needed) --
  \begin{forest} bintree    [A [B] [C]] \end{forest}   binary tree, symmetric
  \begin{forest} genetree   [A [B] [C [D]]] \end{forest} general n-ary tree
  \begin{forest} valbintree [A [B] [C]] \end{forest}   square value nodes
  Missing children in a binary tree: use [,phantom] to reserve the space, e.g.
     bintree [10 [5] [,phantom]]   keeps 5 on the left with an empty right.
  pgfplots: \begin{axis}[bookplot, ...]   (growth curves for 2^h, n log n, Catalan)
  Colours: only names from setup/colors.tex (primaryblue, accentorange, successgreen,
  warningred, softpurple, deepblue, darkgray, lightgray, ...).

MANUAL TREE RECIPE  (use when you must label depths, heights or paths)
  \begin{tikzpicture}[diagram]
    \node[troot] (r) at (0,0)      {A};
    \node[tnode] (b) at (-1.6,-1.5){B};
    \node[tnode] (c) at ( 1.6,-1.5){C};
    \node[tleaf] (d) at (-2.4,-3.0){D};
    \draw[tedge] (r)--(b); \draw[tedge] (r)--(c); \draw[tedge] (b)--(d);
    \node[annot, right=2mm of r] {root, $\depth=0$};
  \end{tikzpicture}
  Give every node a short name ((r),(b),...) so edges and annotations can point at it.

STATE SEQUENCE  (best tool for hard topics: show an operation HAPPEN)
Use whenever an algorithm TRANSFORMS the tree -- BST/AVL rotate, insert, delete,
binary-lifting table fill, HLD path split, lazy push-down, centroid cut. Draw each
snapshot with the manual tree styles, wrap it in a `frame` (the key frame in `framehl`),
number it with a `stepno` badge, and link frames left-to-right with `snap` arrows.
Keep the whole sequence in ONE tikzpicture so the frames stay aligned.

  \begin{figure}[H]\centering
  \begin{tikzpicture}[diagram]
    % frame 1 (before): a left-heavy pair
    \node[tnode] (a1) at (0,0) {3};
    \node[tnode] (b1) at (-0.9,-1.3) {2};
    \draw[tedge] (a1) -- (b1);
    % frame 2 (after): right rotation -> 2 becomes the root
    \node[tnode] (a2) at (3.4,0) {2};
    \node[tnode] (b2) at (4.3,-1.3) {3};
    \draw[tedge] (a2) -- (b2);
    % frames behind the trees (needs the backgrounds + fit libraries)
    \begin{scope}[on background layer]
      \node[frame,   fit=(a1)(b1)] (f1) {};
      \node[framehl, fit=(a2)(b2)] (f2) {};
    \end{scope}
    \node[stepno] at (f1.north west) {1};
    \node[stepno] at (f2.north west) {2};
    \draw[snap] (f1.east) -- (f2.west) node[midway, above, annot] {right rotate};
    \node[framecap, below=1mm of f1.south] {unbalanced};
    \node[framecap, below=1mm of f2.south] {balanced};
  \end{tikzpicture}
  \caption{One right rotation restores balance; the result is boxed in orange.}
  \label{fig:cNN-<slug>-seq}
  \end{figure}

LADDER STAIRCASE  (every opener, per levels.txt \S5: the chapter on the L1..L6 ladder)
  Six rising steps coloured lv1..lv6; the chapter's topics pinned as labels on the
  step they reach. Keep it under \linewidth with a small font; it is a locator map,
  not art.
  \begin{tikzpicture}[diagram, x=10mm, y=8mm]
    \foreach \i [count=\step from 1] in {lv1,lv2,lv3,lv4,lv5,lv6} {
      \fill[\i!25, draw=\i] (\step-1,0) rectangle (\step,\step*0.55);
      \node[font=\scriptsize\bfseries, text=\i] at (\step-0.5,\step*0.55-0.5) {L\step};}
    \node[annot, anchor=south] at (1.5,1.35) {N.1 <topic>};   % pin per topic
    ...
  \end{tikzpicture}
  Caption says: "Beginner path = steps 1-3; the Summit sits on step 6."

WA CLINIC DECISION TREE  (chapter end; TikZ, top-down)
  Root boxnode "Judge verdict?" -> four flow branches WA / TLE / MLE / RE;
  each branch fans into 2-4 leaf boxnodes "cause -> fix" (\textcolor{warningred}{cause}
  then \textcolor{successgreen}{fix} on one line), each leaf ending with a
  \secref/\probref pointer. Only verdicts the chapter can actually produce.
  Use forest for the tree shape (genetree style) or manual TikZ; a compact backup
  tabular follows the figure for long cause lists.

THINKBOX MINI SKETCH  (inside solved_problem.txt step 3)
  One tiny forest tree or 3-node TikZ pair per \deadend when the failed idea is
  structural (wrong rooting, assumed-straight path, missed base case):
    \begin{forest} snaptree [ ... ] \end{forest} with an annot label
    "$\times$ <why this breaks here>"
  Beside the dead-end text (minipage or just the next line); never a full figure
  environment -- these are margin sketches, keep each <= 4 cm wide.

Simple binary snapshots can instead be lined up as small forest trees in a tabular:
  \begin{tabular}{@{}c\quad c\quad c@{}}
    \begin{forest} snaptree [3 [2]] \end{forest} & $\longrightarrow$ &
    \begin{forest} snaptree [2 [,phantom] [3]] \end{forest} \\
    before & & after
  \end{tabular}
Styles: frame, framehl (orange = the key step), stepno (numbered badge), framecap
(caption text), snap (thick orange arrow), snaptree (compact forest tree).

SIZE
- Width <= \linewidth (about 15.9 cm). Level spacing: use l=10..14mm in forest, or
  y-steps of about 1.4..1.6 cm in manual TikZ. Fonts >= \footnotesize.
- If a picture is too wide, scale the coordinates, not the whole picture
  (text must stay readable). A tree wider than the page: split it or shrink s sep.

GOOD DIAGRAMS FOR TREES
- the same tree drawn twice: once bare, once with depth/height/size labels
- subtree highlight (subtreebox around a node and its descendants)
- level bands (a faint rectangle or brace per level, for level-order ideas)
- recursion trace: the call stack as a vertical list beside the tree
- array representation: the tree above, the array cells below, arrows linking index i
  to 2i and 2i+1
- BST search path: highlight the edges from root down to the found/missing key
- segment tree: the tree of intervals with the query range highlighted
- before/after pairs for insert, delete, rotate, rebalance

CHECK
- python tools/preview.py <file> --png <pages> ; open the PNGs and check nothing
  overlaps, nothing is cut off, edges meet node centres, and the colours match the caption.
