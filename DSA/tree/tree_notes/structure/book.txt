TREES FOR COMPETITIVE PROGRAMMING -- BOOK CONTRACT
==========================================================
Target: 23 chapters x about 40 pages = about 920 pages.
Everything below exists so that a large book stays consistent and every
part of it can be edited and compiled on its own.

1. LAYOUT ON DISK  (DSA/tree/tree_notes/)
   tree_notes.tex           root file: parts + one \include per chapter.
                            Edit it only to add, remove or reorder chapters.
   setup/                   THE preamble. The only place for \usepackage, colours,
                            boxes, macros and TikZ/forest styles:
                              packages  colors  layout  macros  boxes
                              theorems  problems  code  diagrams  structure
   frontmatter/             title page, "How to Read This Book" (live style guide), roadmap
   chapters/chNN_slug/      one folder per chapter
     chNN.tex               chapter master: \bookchapter, \chapterinfo, \input's, \closechapter
     00_opener.tex          chapter at a glance, roadmap diagram, topic table, notation
     01_*.tex ... 0K_*.tex  one file per topic = one \section (N.1 ... N.K);
                            K = as many topics as the chapter needs (3-6 typical).
     99_chapter_end.tex     review: summary, checklist, quick reference, mixed set, related topics
   appendices/              formula reference, code templates, strategies
   backmatter/              list of solved problems (automatic)
   structure/               these templates
   tools/                   preview.py (one file, parallel-safe), build.py (whole book)
   build/                   generated files, safe to delete

2. HIERARCHY
   Part (5) > Chapter (23) > Topic = \section (3-6 per chapter, varies) > \subsection (fixed stations) > boxes.
   \section is used only for topics. Opener/review headings use \chaptersection{...}
   (unnumbered, in the TOC) or \subsection*{...} (unnumbered, not in the TOC).

3. ONE HOME PER CONCEPT
   Every definition and theorem is proved in exactly one topic, its "home".
   Everywhere else: a one-line recap plus \thmref{...}. When the outline lists a concept
   in two places, the note in the outline says which one is the home.
   Examples of homes: "n-1 edges" -> 1.1; height vs depth -> 1.2; BST property -> 5.1;
   segment tree build -> 13.1; LCA by binary lifting -> 12.

4. LABELS  (global, never reused)
   <prefix>:c<NN>-<slug>      e.g. thm:c01-edges-nodes  fig:c01-depth-height
                              lst:c03-inorder  prob:c05-bst-insert
   prefixes: ch sec def thm lem cor prop ex fig tab lst prob eq
   Reference with \chref \secref \defref \thmref \lemref \corref \propref \exref
   \figref \tabref \coderef \probref (and \eqref for equations).
   \thmref{c01-edges-nodes} prints "Theorem 1.1.3" as a link.

5. NUMBERS ARE AUTOMATIC
   Problem counts (title page, part pages, chapter header, roadmap) are computed from
   \solvedproblem, \practice and \plannedtopic. Never type a problem count by hand.

6. BUILD
   python tools/preview.py chapters/chNN_slug/03_topic.tex [--png 1-3]   seconds, while writing
   python tools/build.py                                                full book (3 passes + index)
   python tools/build.py --only 1 2                                      only some chapters

7. HARD RULES
   - No \usepackage, \newcommand, \definecolor, \tikzset or \forestset outside setup/.
   - No verbatim, \verb or \lstinline. Code blocks: lstlisting (never inside a macro
     argument). Inline code: \code{...}.
   - ASCII only inside code listings.
   - Every diagram fits \linewidth and its caption says what to notice.
   - Every problem is real: judge + ID + working URL (no % # & in URLs), verified before use.
   - C++ compiles with GCC -std=c++17 as printed, and was run on the samples.
   - Recursion that can go n deep must note the stack risk (iterative alternative).

8. WRITING A NEW CHAPTER
   chapter.txt -> topic.txt (x3-5, uses theory.txt, diagrams.txt, solved_problem.txt,
   practice.txt) -> chapter_end.txt. Then set the chapter's \chapterinfo status to Written.
   Chapter 1 (Tree Basics and Terminology) is the finished reference example.
