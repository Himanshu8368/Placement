NOTES
- CHAPTER SIZING (the split/merge test -- book map v2 in book.txt \S9):
  split a chapter when it would exceed ~15,000 lines / ~200 pages, or when two of
  its topics could each stand as a 3-topic chapter, or when it wants two unrelated
  summits; merge when fewer than 3 lab topics make a composition-summit impossible.
  A chapter is exactly one climbable skill: opener says "you can do X", Summit
  proves "you now do X at the top".
- Topics follow the outline in the stub (\plannedtopic entries): keep its concept
  lists and notes. Reorder topics only if a later topic is needed to prove an earlier
  one, and say so in the chNN.tex header and the opener caption.
- Problem budget per topic: at least 2 fully solved (usually 3) + a practice list
  (the outline's planned count minus the solved ones, at least 4).
- Every tree gets drawn. If a topic mentions a shape, a figure shows it.
- The outline may mark concepts "(added)": they are part of the chapter.

==========================================================================
HARD RULES FOR EVERY CHAPTER
==========================================================================
1. File naming: 00_opener, 01..0K topics (zero-padded), 99_chapter_end.
2. Every .tex starts with the two header comments:
     % !TEX root = ../../tree_notes.tex
     % ==== exports block: labels defined (sec:, thm:, def:, fig:, lst:, prob:)
3. Anti-repetition rule (the DP series' biggest weakness -- do not copy it):
   each fact, formula, trick or warning is stated AUTHORITATIVELY in exactly
   one place, usually its theory station. Everywhere else it may only be
   REFERENCED (\thmref/\secref/\probref/\coderef) or recapped as a bare
   one-line table entry. Never re-derive. Never repeat a worked example.
   The opener PREVIEW-points, the topics TEACH, the end recaps in TABLES only.
4. One running example (same tree/data) per chapter, reused by every topic's
   worked example and trace, so the reader watches one story decomposed.
5. URL rule (book-wide): a problem URL may appear exactly ONCE in the whole
   book.  Check: python tools/urlsweep.py
6. Recognition is a first-class station: the opener carries the chapter-level
   Problem Recognition Guide; each topic carries a pattern card
   (recognitionbox); the chapter end carries the Master Decision Flowchart.
   These three never repeat each other's content:
     opener  = phrasing -> section routing (before the reader knows anything)
     card    = phrasing -> this pattern, incl. when NOT to use it (when learning)
     flowchart = question -> pattern decision ladder (revision, post-chapter)
7. Level badges (levels.txt): every problem, ladder rung, progression tier and
   optional subsection carries \lv{1}..\lv{6}; CF ratings are the OFFICIAL ones,
   never invented. The opener declares the two reading paths and draws the
   chapter's place on the ladder staircase.
8. DIAGRAM-FIRST rule: any new idea, dead end, decision or transformation gets a
   figure before it gets a paragraph (budget in diagrams.txt). A 200-page chapter
   stays readable only if it is roughly one third pictures.
9. Validation loop after writing/editing any file:
     python tools/preview.py chapters/<dir>/<file>.tex     (ERRORS must be 0)
   then chapter level:
     python tools/preview.py chapters/<dir>/chNN.tex
   (fix every overfull >= 10pt at chapter level; inter-chapter undefined refs
   in single-file previews are noise -- only ERRORS count there).
